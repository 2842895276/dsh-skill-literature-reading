# 配置说明（参考）

> **什么时候读这份**：用户问"某节怎么填""路径怎么改"，或配置有争议时。
> **建配置时不用读**——用 `config-template.md` 就够了。

---

## 一、我的方向

**核心方向**决定什么算 `CORE-`。写一句具体的，不要写"计算机"。

好例子：
- 边缘计算的部署方向
- 分布式系统的容错机制

坏例子：
- 计算机（太泛，什么都是 CORE-）

---

## 二、当前阶段

| 阶段 | 判定（只算 CORE-） | AI 该怎么讲 |
|---|---|---|
| 0 零基础 | 精读 < 5 篇 | 每个术语都解释；跳过数学；多用类比 |
| 1 入门 | 精读 5–15 篇 | 术语只首现解释；公式讲"在算什么" |
| 2 有基础 | 精读 15–30 篇 | 假设知道常见缩写 |
| 3 熟悉 | 精读 30+ 篇 | 直接讲差异和争议 |

**阶段只能用户确认才升。** REL- 和 METH- 再多也不算。

## 三、我的背景

这一节**直接决定讲法**，不是装饰。

| 字段 | 影响 |
|---|---|
| 已具备 | 不解释这些内容，直接用 |
| 薄弱 / 没接触过 | 放慢、多类比、先补背景 |
| 最卡在哪 | 那段展开，其他段简略 |
| 讲解偏好 | 优先遵守，盖过默认讲法 |
| 身份 | 决定举例类型（研一用教材例子，工程师用工程例子） |

## 四、知识积累

**只收用户确认搞懂的概念**（能用自己的话说清）。

不收：只是见过名字、还没搞懂的。

## 五、读过的文献

实际内容放在索引文件里，这一节只写一句"见 `<索引路径>`"，避免两处维护。

## 六、知识缺口

读论文时"没看懂但重要"的东西，攒着一起补。出现次数越多越该优先。

## 七、路径配置

### 规则

| 路径类型 | 解释 |
|---|---|
| `./` 开头 | 相对**配置文件所在目录的上一级**（即项目根） |
| `D:\...` 绝对路径 | 直接使用 |
| 目录不存在 | AI 会先创建 |
| 创建失败 | AI 会告诉你具体错误，问要不要换回默认 |

### 常见改法

**PDF 放已有文献库**：
```markdown
| 文献 PDF | `D:\我的文献库\PDF` |
```

**卡片放 Obsidian**：
```markdown
| 文献卡片 | `D:\Obsidian\我的库\文献卡片` |
| 索引 | `D:\Obsidian\我的库\文献卡片\00-index.md` |
```

**全部默认**（最省事）：
```markdown
| 文献 PDF | `./papers/` |
| 文献卡片 | `./cards/` |
| 链接总表 | `./links.md` |
| 索引 | `./cards/00-index.md` |
```

### 改路径的注意事项

> ⚠️ **已存的文献不会自动搬过去**，只影响以后的新文献。
> 要搬旧文件，手动剪切粘贴。

---

## 八、读取策略

**「最近 N 篇」** 决定每次读新论文时额外加载多少历史卡片。

| N | 效果 | 额外开销 |
|---|---|---|
| `0` | 每篇独立，最省 | 0 |
| `1–2` | 能关联最近一两篇 | 2–4KB |
| `3`（默认） | 覆盖最近几次阅读 | 5–6KB |
| `5+` | 上下文最连续 | 10KB+ |

**作用**：让 AI 发现"这篇和你上周读的那篇结论相反"。

**不建议超过 10**——开销线性增长，收益递减。

---

## 九、给 AI 的额外指令

用户直接对 AI 说话的地方，优先级最高。

例：
- "讲实验时重点说为什么这么设计，不用罗列所有数字"
- "我的方向偏工程，多给落地视角"

---

## 最小配置

不想填这么全？三行也能用：

```markdown
# 文献阅读配置

**核心方向**：边缘计算的部署方向
**当前阶段**：0 零基础
**文献路径**：./papers/
```

AI 会按零基础讲，路径全用默认，其他表按需补。
