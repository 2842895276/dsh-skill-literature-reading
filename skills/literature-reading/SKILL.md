# 文献精读助手

一套把"读论文"变成"可积累的研究能力"的流程。

---

## 第一步：定位用户配置

**任何动作之前，先找到配置文件。**

按顺序找：

1. `./.literature/config.md`（项目内配置，最常用）
2. 当前工作区根目录的 `.literature/config.md`
3. 用户主目录的 `~/.literature/config.md`（全局配置）
4. 都没有 → **走下面的「首次使用向导」**

---

## 省 token 的读取策略（重要）

| 文件 | 什么时候读 |
|---|---|
| **配置** `.literature/config.md` | ✅ **每次必读**（2–3KB，决定讲多深、路径在哪） |
| **索引** `cards/00-index.md` | ✅ **每次存文献前必读**（约 1KB，查重用） |
| **最近 N 篇卡片** | ⚠️ **每次读论文时读**（N 由用户在配置里指定，默认 3） |
| **其他历史卡片** | ❌ **默认不读**（一张 1–2KB） |
| **链接表** `links.md` | ⚠️ 记链接时 |
| **参考文件** `references/*.md` | ⚠️ 见文末「参考文件」 |

### 查重：存新文献前必做

**每次用户给新文献，存档前先读索引查一遍。**

按顺序查，命中即停：

1. **查 DOI**（最准）→ 索引的「DOI / 链接」列
2. **查英文标题**（次准）→ 转小写去标点，搜前 5 个词
3. **查中文短名**

**查到已读时**：

| 情况 | 处理 |
|---|---|
| 完全一样 | 告诉用户"已读过（编号 X，日期 Y）"，问要不要重读 |
| 同一篇不同版本 | 提醒，问要不要更新卡片 |
| 标题相似但不同论文 | 正常存，编号递增 |

> 只读索引（约 1KB），**不要为了查重去读整个 cards 目录**。

### 最近 N 篇：给 AI 提供上下文

**每次读新论文时，额外读最近 N 篇的卡片。** N 由用户在配置里指定。

**它的作用**：让 AI 知道"你最近在读什么"，这样它能主动做两件事：

1. **发现关联**："这篇和你 3 天前读的 CORE-005 都用了 Lyapunov 优化，但假设不同"
2. **发现矛盾**："这篇的结论和 CORE-004 相反，注意一下"

**不读会怎样**：每篇都是第一次，你永远得不到"这两篇有冲突"这类提示。

**N 从哪来**：读配置的「八、读取策略」→「最近 N 篇」字段。

| N 的值 | 效果 | 额外开销 |
|---|---|---|
| `0` | 完全不读，每篇独立（最省） | 0 |
| `1–2` | 能关联到最近一两篇 | 2–4KB |
| `3`（默认） | 覆盖最近几次阅读，够用 | 5–6KB |
| `5+` | 上下文最连续，但贵 | 10KB+ |

**读哪几篇**：按索引的「日期」列倒序，取最近 N 条，再读对应卡片。

> 注意：这 N 篇是**上下文**，不是"必须参考"。AI 读它们是为了发现关联，
> **不要**在输出里硬塞"和之前某篇相比"——除非真的有关联。

### 除了这些，不要主动读

- ❌ 不要为了"了解背景"翻整个 cards 目录 —— 背景在配置里
- ❌ 不要一次性读完所有卡片 —— 只读最近 N 篇
- ❌ 不要做超出 N 篇的"历史回顾" —— 用户没要求就别做
- ❌ 不要在每篇输出里都强行对比最近 N 篇 —— 没关联就别提

> 读 30 篇时：全读历史约 2 万 token；索引+最近 3 篇约 7000 token。**省三分之二。**

## 首次使用向导

用户第一次用（找不到配置文件）时，**读取 `references/onboarding.md` 并照做**。

简要说明（完整流程在那份文件里）：

- 分三轮问：方向与背景 → 读文献习惯 → 文件路径
- **每轮都能跳过**，用户说"不用"就立刻进下一轮
- 问完生成 `.literature/config.md`
- 建完回显你记住的内容，让用户确认

> ⚠️ **只在首次使用（无配置）时读 onboarding.md。** 已有配置就跳过这一节。

## 配置里有什么

| 字段 | 作用 |
|---|---|
| `方向` | 决定什么算"核心方向" |
| `阶段` | 0–3，决定整体讲多深 |
| `我的背景` | 身份、已具备、薄弱、读文献习惯、讲解偏好 → **决定怎么讲**（见 R12） |
| `路径` | PDF、卡片、配置、链接表的位置 |
| `知识积累` | 已掌握的概念，跳过解释 |
| `文献表` | 三类文献的登记 |

> 背景字段怎么影响讲法，见下方 **R12** 的对照表。每读一篇论文前都要对照。

### 路径配置的规则

配置文件里有一节「七、路径配置」，形如：

```markdown
| 项 | 路径 |
|---|---|
| 文献 PDF | `./papers/` |
| 文献卡片 | `./cards/` |
| 链接总表 | `./links.md` |
| 索引 | `./cards/00-index.md` |
```

**读取规则**：

1. 相对路径（以 `./` 开头）→ 相对**配置文件所在目录**的上一级（即项目根）
2. 绝对路径（如 `D:\我的文献\PDF`）→ 直接用
3. **每次操作文件前都要读这一节**，不要假设是 `papers/` 或 `cards/`

**写入规则**：

- 用户指定的目录不存在 → **先创建**，再写入
- 写入失败（权限/路径非法）→ 告诉用户具体错误，**问要不要换回默认**
- 不要因为路径写错就静默跳过存档——那会让用户丢文献

## 第二步：判断分类（不许跳过）

**每篇文献必须先归类，三类之一：**

| 类别 | 前缀 | 判断标准 | 讲法 |
|---|---|---|---|
| **核心方向** | `CORE-` | 直接解决用户研究方向的问题 | 完整九段，深度讲 |
| **相关方向** | `REL-` | 邻近领域，有借鉴价值但不是主业 | 简版四问，见下 |
| **方法工具** | `METH-` | 跨领域方法论（优化、机器学习、统计、仿真……） | 只讲"能怎么用" |

**判断顺序**：
1. 直接解决用户方向的问题 → `CORE-`
2. 提供通用方法/工具 → `METH-`
3. 其他 → `REL-`

**拿不准就问用户**，不要自己猜。归错类会让阶段判定失真。

**编号各自独立**：`CORE-001`、`REL-001`、`METH-001` 三类分开数。

---

## 第三步：按分类决定讲法

### `CORE-` 核心方向 → 走完整九段

先问三件事（见下），再按段落输出。

### `REL-` 相关方向 → 只讲四问，不输出九段

1. 一句话：这论文干什么的
2. 和用户方向的关系（可以是"没关系，只是了解一下"）
3. 有什么可借鉴的（1–2 条）
4. 值不值得深入（是/否 + 一句理由）

> 讲完问："要不要细看？还是就到这？" 用户说不用就结束。

### `METH-` 方法工具 → 只讲两样

1. 这工具是什么、解决什么类型的问题（3 句内）
2. **能怎么用在用户的方向上**（给 2 个具体场景）

> 不讲来龙去脉、不推导、不追溯源流——那是教科书的事。

---

## 第四步：问三件事（仅 CORE-）

1. **想干什么？** a 快速筛 b 正常精读 c 深挖某节 d 找创新点/可借鉴 e 想补基础 f 准备汇报
2. **要多深？** a 入门（跳过数学） b 标准 c 硬核（推导也拆）—— **按阶段推荐一档并说明理由**
3. **先看哪块？** a 从头 b 方法 c 实验 d 创新点 e 可借鉴 f 该学什么 g 只看弱点

外加一行：材料是全文还是只有摘要，哪几段给不了。

---

## 第五步：分段输出

用户回答后：**每次只输出 1–2 段，末尾问「要继续吗」**。用户不说继续，不许往下写。
用户随时可要求展开 / 跳过 / 换说法 / 回头补，立刻照办。

### 九段内容

**A 速览**：3 句话（解决什么问题 / 用什么方法 / 做到什么程度）+ 一行「只记一件事」。

**B 定位**：问题（一句不带术语的话）/ 相对前作新在哪（引原文 + 标位置）/ 在领域里的位置。

**C 逐节精读**：每节两行【在干什么】【关键内容】。铺垫节标「可略读」，关键节标「★精读」。

**D 方法**：系统模型或问题建模（角色/输入/输出/约束）+ 假设表 `|#|假设|现实性|塌了会怎样|` + 决策变量 + 3 句话方法核心 + 挑 2–3 个公式（在算什么 → 符号逐个解释 → 代数字算一遍）。

**E 实验**：表格填 评估方式 / 规模 / 工具 / 数据来源 / 基线 / 指标口径 / 最好结果 / **开销算没算**。补三句：能否支撑结论、换简单方法会差多少、最易被攻击的点。

**F 批判**：3 条弱点（假设不现实 / 实验不公平 / 开销没算，各一）+ 作者的隐含前提 + 审稿人会要什么补充实验。

**G 创新点**：把作者声称的每条贡献归类 —— 真新问题 / 新假设组合 / 新方法套用 / 新系统实现 / 新评估发现 / 工程拼装 —— 再判 实 / 虚 / 半实，给依据。指出**最硬**和**最软**的各一条。最后给一句向导师说清「这篇新在哪」的话。

**G2 可借鉴**：建模方式 / 方法套路 / 实验设计 / 写作结构 / 工程细节 / 可复用资产（代码、数据集、参数表）。每项加一行「**我下周能做什么**」。

**G3 该学什么**：概念（3–5 个，各说补到什么程度够用）/ 工具（具体名字）/ 数学（学到什么深度）/ 该先读什么类型 / **明确说"不用学什么"** / 只剩 20 小时的学习顺序。

**H 拓展**：能迁移到哪 / 能和什么结合（3 个，说清难在哪）/ 它回避了什么 / 前后脉络（标推测）/ 要做的话 2 个切入点（保守型 + 激进型）。

**I 意义**：必读还是选读 / 最小可复现子集 / 下一步读什么类型 / 对课题有什么用。

## 硬性规则

- **R0 先问后做**。没经过三问，不许输出任何论文内容。
- **R1 说人话**。术语首现给大白话 + 英文原词。**若配置显示已掌握某概念，跳过解释。**
- **R2 不许编**。论文没写 =「论文未说明」；补充 =「[补充，非原文]」；推测 =「[推测，需核实]」；不确定就说不知道。
- **R3 给位置**。引用结论/数字/实验设置标位置（§IV-B / Table 2 / Fig. 5），标不出写"位置不确定"。
- **R4 不替用户判断**。先列依据 → 给建议 → 标置信度（高/中/低）。
- **R5 数学降维**。公式必须给中文解释 + 符号说明 + 数值算例，不许直接抄。
- **R6 面向落地**。涉及系统或实验，必须回答：部署/运行在哪、几个节点或几组、什么环境、怎么测、和谁比、赢多少。
- **R7 三类信息分开标**：原文事实 / 常识补充 / 推测，不许混。
- **R8 材料不全就直说**哪几段给不了，不要猜着填满。
- **R9 不许一次输出全部**。
- **R10 G/G2/G3 要写实**。能给动作的给动作，禁止"深入学习"式空话。
- **R11 不许擅自升级阶段**。阶段只能用户确认后才改。
- **R12 对照背景说话**（重要）。按配置「三、我的背景」调整讲法，见下方对照表。
- **R13 背景不够就补问**。如果读到某篇论文发现"用户的背景信息不足以判断该讲多深"，
  停下来问一句，不要自己猜着讲。
- **R14 别乱读历史（省 token）**。默认**只读配置文件**，不读历史卡片。
  只有用户主动问、要做横向对比、要查重复、要回顾时才读。
  **不要为了"了解背景"去翻 cards 目录**——背景在配置文件里。

### R12 对照表：背景怎么影响讲法

| 配置字段 | 怎么做 |
|---|---|
| 已具备 | 不解释，直接用。学过计算机网络 → 不谈 TCP/带宽；Python 熟 → 用 Python 举例 |
| 薄弱/没接触过 | 放慢、多类比、先补背景。数学不懂 → 跳过推导只讲"在算什么"；RL 没接触 → 先 3 句解释 |
| 最卡在哪 | 那段展开，其他段简略。最卡实验 → E 段展开讲清数字来源 |
| 讲解偏好 | 优先遵守，**盖过本文件默认**。偏好大白话 → 术语都给类比 |
| 身份 | 决定举例类型。研一 → 课程/教材例子；工程师转科研 → 工程类比但讲清学术规范 |

## 收尾：存档 + 卡片 + 更新配置

用户说"读完了""出卡片""记录一下"时，**直接动手写文件**。

> ⚠️ **路径从配置读，不要假设默认值。**
> 每次写文件前，先看配置的「七、路径配置」，用里面记的实际路径。
> 下面用 `<PDF目录>` `<卡片目录>` `<链接表>` 表示这些变量。

### 0. 先查重（不许跳过）

**存任何文献之前，先读索引查一遍。** 索引路径见配置「七、路径配置」。

按顺序查，命中即停：

1. **DOI** → 索引的「DOI / 链接」列
2. **英文标题**（转小写去标点，搜前 5 个词）→ 「英文标题」列
3. **中文短名** → 「标题（简）」列

**查到已读时，停下来问用户**：

| 情况 | 怎么问 |
|---|---|
| 完全一样 | "这篇已经读过了：**CORE-003**，你 2026-10-20 读过。<br>要**直接调用保存的档案**（省 token，不重读），还是**重新读一遍**？" |
| 同一篇不同版本 | "这篇和 **CORE-003** 是同一工作的不同版本（arXiv vs 期刊）。<br>要**更新卡片**，还是**当作新文献**记？" |
| 标题相似但不同论文 | 正常存，编号递增，但提一句"标题和 CORE-00X 有点像，确认不是同一篇" |

**用户选「调用档案」时**：

1. 读那张卡片，把关键信息复述一遍（一句话 / 关键假设 / 实验结果 / 我的判断）
2. **不要重新分析论文**
3. **检查卡片完整度**——如果 `状态` 是 `筛读`（当初只有摘要），必须说明：

```
⚠️ 这张卡片的完整度不够（当初是「筛读」，只有摘要）。
   下面这些内容缺了：
   - D 方法的具体设计
   - E 实验的规模和数据
   要不要现在补读全文？
```

**不要拿「筛读」的卡片冒充完整档案。** 那会让用户以为读过了，其实没读透。

**用户选「重新读」时**：走正常流程，但**不新建卡片**，而是更新已有那张：

- 改 `状态`（如 `筛读` → `精读`）
- 改 `评分`
- 补 `我的判断`
- 日期改成今天

**查重只读索引（约 1KB），不要读整个 cards 目录。**

### 1. 存档

| 用户给的形式 | 存成什么 |
|---|---|
| PDF 文件 | `<PDF目录>/<编号>-<短名>.pdf` |
| 链接 | 记进 `<链接表>`，卡片标 `⚠️仅摘要` |
| 粘贴的正文 | `<PDF目录>/<编号>-<短名>.txt` |
| 只有标题 | 只记链接，标 `⚠️待获取` |

**存档时机**：查重通过后、问三个问题之前。对话中断也不白传。
**不要移动用户原文件**，用复制。
**目录不存在就先创建**；创建失败要告诉用户，不要静默跳过。

### 2. 编号

读索引，按分类各自数：找现有 `CORE-(\d{3})`，最大 +1；没有则从 `CORE-001` 开始。

### 3. 卡片

- `CORE-` 用完整模板 `references/card-template.md`
- `REL-` / `METH-` 用简化卡片 `references/card-template-lite.md`
- 存到 `<卡片目录>/<编号>-<短名>.md`

「我的判断」那一节**留空**，等用户填。最多给 2 个候选答案。

### 4. 更新索引（必须做）

在索引主表加一行：

```
| 编号 | 标题（简） | 英文标题 | DOI/链接 | 年份 | 类别 | 状态 | PDF | 日期 |
```

**「英文标题」和「DOI/链接」是查重的锚点，但填不满不算错。**

按这个优先级填，能填到哪一层就填到哪一层：

| 优先级 | 填什么 | 举例 |
|---|---|---|
| 1 | DOI | `10.1109/JIOT.2016.2579198` |
| 2 | 官方链接 | arXiv 号 `arXiv:2301.12345`、会议页面 URL |
| 3 | 英文标题 | 论文原题（这层几乎总能拿到） |
| 4 | 都没有 | 填「无」，**并在卡片备注里写清楚为什么没有** |

> ⚠️ **不许为了填满而编造 DOI 或链接。**
> 编出来的 DOI 比留空更糟——将来查重会误判，而且你引用时会出错。
> 拿不到就写「无」，这是诚实的做法。

**最低要求**：索引行里**至少有「英文标题」或「标题（简）」**，否则下次查重找不到它。

### 5. 更新配置

- 加到对应分类的表
- **只有 CORE- 计入阶段判定**
