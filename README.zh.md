# 文献阅读技能

> 读论文 → 自动存档 → 出卡片 → 能力档案成长
>
> 一个 [DeepSeek Harness](https://github.com/deepseek-ai) 技能。

[English](README.md) | 中文

**研究生读文献最痛的不是看不懂英文，是读完了什么都没留下。**

这个技能让每读一篇都留下三样东西：原文存档、结构化卡片、成长的能力档案。

---

## 安装

### 最简单：双击安装

```
① 下载 ZIP（绿色 Code 按钮 → Download ZIP）→ 解压
② 进 install\ 双击 install.cmd
③ 弹出菜单后直接按回车（默认装到全局）
④ 重启 DSH，新建对话说「读这篇论文」
```

**就这四步。** 不用命令行，不用 npm，不用注册账号。

### 另外三种方式

| 方式 | 适合谁 | 怎么做 |
|---|---|---|
| **全局安装**（上面那个） | 想在所有项目都用 | 双击 → 回车 |
| **装到单个项目** | 只想在一个项目用，**不占 C 盘** | 双击 → 选 2 → 输入项目路径 |
| **手动复制** | 想完全掌控 | 把 `skills/literature-reading` 复制到 `<项目>/.dsh/skills/` |
| **其他桌面端** | 用 Cursor / Claude | 双击 → 选 4，看平台说明 |

> 全局装到 `C:\Users\你的用户名\.agents\skills\`
> 项目级装到 `<你的项目>\.dsh\skills\` —— **完全不碰 C 盘**

### 技能能装在哪

**装的位置必须是客户端能识别的，否则装了用不了。**

| 优先级 | 位置 | 需要 C 盘 | 生效范围 |
|---|---|---|---|
| 100 | `<项目>/.dsh/skills/` | ❌ | 只有那个项目 |
| 200 | `<项目>/.agents/skills/` | ❌ | 只有那个项目 |
| 300 | 自定义目录（需注册） | ❌ | 视配置 |
| 400 | `~/.dsh/skills/` | ✅ | 所有项目 |
| 500 | `~/.agents/skills/` | ✅ | 所有项目 |

### 验证装好了没

新建对话，说「读这篇论文」。**它应该先问你几个问题**，而不是直接分析。

没反应的话见 [QUICKSTART.md](QUICKSTART.md) 的排查章节。

## 核心创新

### 一、三分类：只有核心方向计入你的水平

```
                    ┌─────────────────────┐
                    │   你读到一篇论文     │
                    └──────────┬──────────┘
                               ↓
                  ┌────────────┴────────────┐
                  │  它直接解决你方向的问题？ │
                  └────────────┬────────────┘
                    是 ┌───────┴───────┐ 否
                       ↓               ↓
              ┌────────────────┐  ┌────────────────────┐
              │   CORE-        │  │ 它提供通用方法/工具？ │
              │   核心方向      │  └─────────┬──────────┘
              └────────┬───────┘      是 ┌───┴───┐ 否
                       │                ↓       ↓
                       │        ┌──────────┐ ┌──────────┐
                       │        │  METH-   │ │  REL-    │
                       │        │ 方法工具  │ │ 相关方向  │
                       │        └────┬─────┘ └────┬─────┘
                       ↓             ↓            ↓
              ┌─────────────┐ ┌───────────┐ ┌───────────┐
              │  完整九段    │ │  只讲两样  │ │  简版四问  │
              └──────┬──────┘ └─────┬─────┘ └─────┬─────┘
                     ↓              ↓             ↓
              ┌──────────────────────────────────────────┐
              │  ✅ 计入水平          ❌ 不计入水平        │
              └──────────────────────────────────────────┘
```

**为什么重要**：读 20 篇相邻领域的综述，不会让你成为本方向的入门者。
但如果档案把它算成"读了 20 篇"，AI 就会按"有基础"的方式讲——你反而更听不懂。

| 类别 | 前缀 | 讲法 | 计入水平 |
|---|---|---|---|
| 核心方向 | `CORE-` | 完整九段，深度讲 | ✅ |
| 相关方向 | `REL-` | 简版四问，快速过 | ❌ |
| 方法工具 | `METH-` | 只讲"能怎么用" | ❌ |

### 二、先问后做，分段交付

它不会一上来就把 8000 字倒给你：

```
你：读这篇论文 + PDF
        ↓
AI：📥 已存档：papers/CORE-001-xxx.pdf
    这是核心方向文献。
    【问题1】这次想干什么？  a 快速筛  b 精读  c 深挖  d 找创新  e 补基础  f 汇报
    【问题2】要多深？        a 入门  b 标准  c 硬核
    【问题3】先看哪块？      a 从头  b 方法  c 实验  d 创新点  e 可借鉴  f 该学什么  g 弱点
        ↓
你：b，标准版，从头
        ↓
AI：[A 速览 + B 定位] 要继续吗？
        ↓
你：继续 / 跳过实验 / 方法讲细点
```

**为什么**：一次性吐完，你多半只看了开头和结尾。

### 三、自动存档，对话断了也不丢

| 你给的 | 存成什么 |
|---|---|
| PDF 文件 | `papers/CORE-001-xxx.pdf` |
| 链接 | 记进 `links.md`，卡片标 `⚠️仅摘要` |
| 粘贴的正文 | `papers/CORE-001-xxx.txt` |
| 只有标题 | 只记链接，标 `⚠️待获取` |

**存档发生在问你三个问题之前。** 对话中断也不白传。

### 四、能力档案会成长

```
阶段 0（<5 篇）   每个术语都解释，跳过数学
阶段 1（5–15）    术语只在首现解释
阶段 2（15–30）   假设你知道常见缩写
阶段 3（30+）     直接讲差异和争议
```

读得越多 → 讲得越深 → 越读越快。

**阶段只能你自己确认才升。** AI 不许因为读了一篇就判你"入门了"。

### 五、九段拆解

| 段 | 内容 |
|---|---|
| **A 速览** | 3 句话 + 只记一件事 |
| **B 定位** | 解决什么问题、站在谁的肩膀上 |
| **C 逐节精读** | 标注「可略读 / ★精读」 |
| **D 方法** | 假设表、决策变量、公式降维 |
| **E 实验** | 规模、基线、指标口径、**开销算没算** |
| **F 批判** | 三条弱点 + 隐含前提 |
| **G 创新点** | 真创新还是包装？逐条归类 |
| **G2 可借鉴** | 建模/方法/实验/写作/工程，各能抄什么 |
| **G3 该学什么** | 分三档，附"不用学什么" |

### 六、省 token：只读该读的

读得越多，历史卡片越多。如果每次都翻一遍，读 30 篇后每篇要多烧 2 万 token。

所以它**按需读取**：

| 读什么 | 什么时候 | 开销 |
|---|---|---|
| 配置文件 | 每次必读 | 约 2.5KB |
| 索引表 | 存新文献前查重 | 约 1KB |
| **最近 N 篇卡片** | 每次读新论文时 | N 由你指定 |
| 其他历史卡片 | 只有你问了才读 | — |

### 最近 N 篇：你自己定

配置里有一项「最近 N 篇」，决定每次读新论文时带上多少上下文：

| N | 效果 | 额外开销 |
|---|---|---|
| `0` | 每篇独立，最省 | 0 |
| `1` | 能说"和上一篇比" | 约 2KB |
| **`3`（默认）** | 覆盖最近几次阅读 | 约 5KB |
| `5` | 上下文更连续 | 约 10KB |

**为什么要有这个**：完全不带历史，AI 就不知道"你上周读过一篇观点相反的论文"。
带太多又浪费。所以交给用户按需调。

### 查重：不会重复存同一篇

**每次存新文献前，先查索引表**（约 1KB，不是读所有卡片）：

1. 查 **DOI**（最准）
2. 查 **英文标题**（转小写搜前 5 个词）
3. 查中文短名

命中就停下来问你：

> "这篇已经读过了：**CORE-003**，你 2026-10-20 读过。
> 要**直接调用保存的档案**（省 token，不重读），还是**重新读一遍**？"

| 你的选择 | 它会做什么 |
|---|---|
| **调用档案** | 读那张卡片，复述关键信息，**不重新分析论文** |
| **重新读** | 走正常九段流程，但**更新已有卡片**，不新建 |

**还会检查档案完整度**：如果那张卡片当初只是「筛读」（只有摘要），它会明确告诉你缺了什么：

```
⚠️ 这张卡片的完整度不够（当初是「筛读」，只有摘要）。
   下面这些内容缺了：
   - D 方法的具体设计
   - E 实验的规模和数据
   要不要现在补读全文？
```

**不会拿残缺卡片冒充完整档案。**

**索引表专门为查重设计**，每行只有几十字节：

```
| 编号 | 标题（简） | 英文标题 | DOI/链接 | 年份 | 类别 | 状态 | PDF | 日期 |
```

**字段填不满不算错。** 按 DOI → 链接 → 英文标题 → 「无」的顺序回退。

> ⚠️ **不许为了填满而编造 DOI。** 编出来的 DOI 比留空更糟——将来查重会误判。

### 省下来的量

| 策略 | 读 30 篇后每篇开销 |
|---|---|
| 全读历史 | 约 22000 token |
| **索引 + 最近 3 篇**（默认） | 约 7000 token |

**省三分之二**，而且读得越多差得越大。

```
│  ├─ papers/                 PDF 存放目录（空的）
│  └─ links.md                链接总表示例
│
├─ docs/          📚 文档。用的时候查
│  ├─ manual.md            完整教程（卡片怎么填、档案怎么长）
│  ├─ design.md            设计原理和架构图
│  └─ files.md             每个文件干什么的（维护者看）

├─ README.zh.md   📄 本文件
├─ README.md      英文版
├─ QUICKSTART.md  安装教程
│

├─ LICENSE             MIT 协议
└─ .gitignore          防止误提交私人文件
```

### 你实际需要哪个

| 你想做什么 | 用哪个文件夹 |
|---|---|
| **装技能** | `install/`（双击）或 `skills/`（手动复制） |
| **看示例配置** | `example/` |
| **查文档** | `docs/` |
| **其他都不用管** | `package.json`、`cordis.patch.yml` |

### 装好之后你的项目会变成这样

```
你的项目/
├─ .literature/
│  └─ config.md              ← 你的方向、水平、积累
├─ papers/                   ← 📄 原文 PDF
│  └─ CORE-001-xxx.pdf
├─ cards/                    ← 📝 文献卡片
│  ├─ 00-index.md
│  └─ CORE-001-xxx.md

```

> ⚠️ **不要直接改 `example/` 里的文件**——那是示例，改了自己项目的配置不会变。

## 使用过程

### 第一次：建配置

技能发现没有 `.literature/config.md`，会**分三轮**问你。**每轮都能跳过。**

**第一轮：方向与背景**

```
1. 你的研究方向是什么？（如"边缘计算的部署方向"）
2. 你的身份/阶段？（研一 / 研二 / 博一 / 工程师转科研）
3. 你学过哪些相关课程？（计算机网络、操作系统…）
4. 你会什么工具/语言？（Python 熟、C 会一点…）
5. 你在哪方面最薄弱？（数学公式、分布式系统…）
```

**第二轮：读文献习惯**

```
6. 你现在的水平？0 零基础 / 1 入门 / 2 有基础 / 3 熟悉
7. 你读文献最卡在哪？看不懂方法 / 看不懂实验 / 读完就忘
8. 你更想要哪种讲法？大白话 / 正常学术 / 直接讲要点
```

**第三轮：文件路径**

```
papers/  cards/  .literature/  links.md

直接回"不用" = 全部默认
```

**只想快点开始**：只答第 1 条，其余全跳过，AI 按零基础处理。

### 为什么要问背景

**这不是走流程，是真影响讲法的。**

| 你在配置里写了 | AI 会怎么做 |
|---|---|
| 学过计算机网络 | 讲网络概念时不解释 TCP、带宽 |
| Python 熟 | 代码示例用 Python |
| 数学公式看不懂 | 跳过推导，只讲"在算什么" |
| 强化学习没接触过 | 遇到 DRL 先花 3 句解释它是什么 |
| 最卡在实验部分 | 实验段展开讲，其他段简略 |
| 偏好大白话 | 所有术语都给生活化类比 |
| 研一 | 举例用课程/教材里的东西 |

### 四个位置都能自定义

| 项 | 默认 | 可改成 |
|---|---|---|
| **文献 PDF** | `./papers/` | 任何路径，如 `D:\我的文献库\PDF` |
| **文献卡片** | `./cards/` | 如 Obsidian 库里的目录 |
| **链接总表** | `./links.md` | 任意位置 |
| **索引** | `./cards/00-index.md` | 跟着卡片目录走 |

**相对路径**相对项目根，**绝对路径**直接用。

### 日常使用

```
你：读这篇论文
    [拖入 PDF]
        ↓
AI：📥 已存档：papers/CORE-001-xxx.pdf
    这是核心方向文献。
    【问题1】这次想干什么？...
    【问题2】要多深？...
    【问题3】先看哪块？...
        ↓
你：b，标准版，从头
        ↓
AI：[输出 A 速览 + B 定位] 要继续吗？
        ↓
你：继续
        ↓
AI：[输出 C 逐节 + D 方法] 要继续吗？
        ↓
    …… 一直到 I 意义 ……
        ↓
你：出卡片
        ↓
AI：写卡片 → 更新索引 → 更新配置
```

### 六种常用开场（直接抄）

| 场景 | 直接回这句 |
|---|---|
| 快速判断值不值得读 | `a，入门版，先看 A 和 F` |
| 认真读懂一篇 | `b，标准版，从头开始，一段一段来` |
| 想知道这篇新在哪 | `d，硬核版，先看 G 创新点` |
| 想知道我能抄什么 | `d，标准版，先看 G2，重点讲工程细节` |
| 想知道该补什么基础 | `e，标准版，先看 G3，按"现在该补"排` |
| 要组会汇报 | `f，标准版，先看 A、B、E、F` |

### 你随时可以打断

| 你想做什么 | 说什么 |
|---|---|
| 某段讲太浅 | `D 再讲细一点` |
| 某段不用看 | `跳过 E，直接给我 G` |
| 换个说法 | `刚才那段用大白话重讲` |
| 只问一点 | `这篇用的什么仿真器？` |

### 以后想改路径

改 `.literature/config.md` 的「七、路径配置」那一节，立即生效。

> ⚠️ 已存的文献不会自动搬过去，只影响新文献。

## 实例

### 实例 1：一份填好的配置

`.literature/config.md` 长这样：

```markdown
# 文献阅读配置

#### 一、我的方向
**核心方向**：边缘计算的部署方向
**关注的具体问题**：
- 服务放置（Service Placement）
- 任务卸载（Offloading）

#### 二、当前阶段
| 项 | 值 |
|---|---|
| **阶段** | 0 零基础 |
| **核心方向·已精读** | 3 篇 |

#### 三、我的背景
##### 身份
**我是**：研一

##### 已具备
| 学过课程 | 计算机网络、操作系统、数据结构 |
| 会用的工具 | Python（熟）、Linux 命令行 |

##### 薄弱
| 最薄弱的地方 | 数学公式看不懂 |
| 完全没接触过 | 强化学习、凸优化 |

##### 讲解偏好
- 术语第一次出现时都要解释
- 公式先讲"在算什么"，再给符号

#### 七、路径配置
| 项 | 路径 |
|---|---|
| 文献 PDF | `./papers/` |
| 文献卡片 | `./cards/` |
```

### 实例 2：一份填好的卡片

`cards/CORE-001-xxx.md` 长这样：

```markdown
---
编号: CORE-001
标题: Edge Computing: Vision and Challenges
短名: Shi2016-边缘计算愿景
年份: 2016
类型: 综述
状态: 精读
评分: 4
链接: https://doi.org/10.1109/JIOT.2016.2579198
链接状态: ✅全文
PDF: papers/CORE-001-Shi2016.pdf
---

#### A 一句话
> 定义了边缘计算的三个关键场景，提出五个待解决问题。

#### B 它新在哪
- 贡献：首次系统定义边缘计算的内涵与外延
- **最硬的一条**：把"边缘"从模糊概念拆成可讨论的三类场景
- **最软的一条**：挑战部分只是列举，没有量化

#### C 关键假设
| # | 假设 | 现实性 | 塌了会怎样 |
|---|---|---|---|
| 1 | 边缘节点有足够算力 | 中 | 低算力场景下结论不成立 |

#### G 我的判断（我自己写）
- 这篇对我有用吗：**有用**，它是我理解领域边界的锚点
- 我信它的结论吗：**信定义，不信挑战清单**——后者太泛
- 它最可疑的地方：说"边缘"时没区分基站 MEC 和园区网关
- 读完我想到的新问题：如果把边缘节点算力再降一档，哪些场景还成立？
```

### 实例 3：一次完整对话

```
【你】
读这篇论文
[附上 PDF]

【AI】
📥 已存档：papers/CORE-001-Shi2016.pdf
```

## 设计理念

1. **AI 负责降维、结构化、翻译、挑刺、延伸；你负责判断。** 判断权不能外包。
2. **卡片里「我的判断」必须自己写。** 全让 AI 写，你只是"看过"，不是"读过"。
3. **AI 的分析读起来很顺，会让你误以为自己懂了。** 破解方法：隔几天，合上所有材料，用三句话复述一篇论文。
