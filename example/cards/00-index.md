# 文献索引（示例）

> **这份文件是查重和查编号的唯一入口。**
> 每次存新文献前，先在这里搜一遍，确认没读过。
> 比读卡片便宜得多——一张卡片 1–2KB，一行索引只有几十字节。

| 前缀 | 类别 | 计入阶段 | 卡片要求 |
|---|---|---|---|
| `CORE-` | 核心方向 | ✅ | 完整九段 |
| `REL-` | 相关方向 | ❌ | 简化卡片 |
| `METH-` | 方法工具 | ❌ | 简化卡片 |

**三类各自编号**：`CORE-001`、`REL-001`、`METH-001` 互不占用。

## 查重怎么做

存新文献**之前**，按这个顺序查：

### 1. 查 DOI（最准）

如果新文献有 DOI，直接在索引的「DOI / 链接」列搜。

```
命中   → 已读过，告诉用户"这篇是 CORE-003，你 10 月 20 日读过"
未命中 → 继续查标题
```

### 2. 查英文标题（次准）

把论文原题转小写、去掉标点，在「英文标题」列搜前 5 个词。

```
命中   → 可能是同一篇（也可能是不同版本的同一篇）
未命中 → 继续查中文短名
```

### 3. 查中文短名

```
命中   → 同一篇
未命中 → 新文献，可以存
```

### 查到已读怎么办

**不要直接跳过，停下来问用户。**

| 情况 | 怎么问 |
|---|---|
| 完全一样 | "这篇已经读过了：**CORE-003**，你 2026-10-20 读过。<br>要**直接调用保存的档案**（省 token，不重读），还是**重新读一遍**？" |
| 同一篇但版本不同 | "这篇和 **CORE-003** 是同一工作的不同版本（arXiv vs 期刊）。<br>要**更新卡片**，还是**当作新文献**记？" |
| 标题相似但不同论文 | 正常存，编号递增，提一句"标题和 CORE-00X 有点像，确认不是同一篇" |

### 用户选「调用档案」时

读那张卡片，把关键信息复述一遍：一句话、关键假设、实验结果、我的判断。

**不要重新分析论文。** 这是这个选项的意义——省时间也省 token。

### 用户选「重新读」时

走正常九段流程，但**不新建卡片**，而是更新已有那张：

- 改 `状态`（比如 `筛读` → `精读`）
- 改 `评分`
- 补 `我的判断`
- 日期改成今天

## 字段填不满怎么办

**「英文标题」和「DOI/链接」是查重的锚点，但填不满不算错。**

按优先级填，能填到哪层就填到哪层：

| 优先级 | 填什么 | 举例 |
|---|---|---|
| 1 | DOI | `10.1109/JIOT.2016.2579198` |
| 2 | 官方链接 | `arXiv:2301.12345`、会议页面 URL |
| 3 | 英文标题 | 论文原题（这层几乎总能拿到） |
| 4 | 都没有 | 填「无」，并在卡片备注里说明原因 |

> ⚠️ **不许为了填满而编造 DOI 或链接。**
> 编出来的 DOI 比留空更糟——将来查重会误判，你引用时也会出错。

**最低要求**：至少有「英文标题」或「标题（简）」，否则下次查重找不到它。

## 读取策略

| 场景 | 读什么 | 开销 |
|---|---|---|
| **存新文献前查重** | 只读这份索引 | 约 1KB |
| 分配新编号 | 只读这份索引 | 约 1KB |
| 看"我读过什么" | 只读这份索引 | 约 1KB |
| 要看某篇的详细内容 | 读对应那一张卡片 | 1–2KB |

> ⚠️ **不要为了查重去读整个 cards 目录。** 索引就是为这个存在的。

---

## 状态说明

| 状态 | 含义 |
|---|---|
| `筛读` | 只看了摘要，判断值不值得读 |
| `精读` | 全文读过，出了卡片 |
| `复现` | 动手做过实验 |
| `弃读` | 判断无价值，记录原因 |

## 文件命名

```
文献卡片/CORE-001-Shi2016-边缘计算愿景.md
文献PDF /CORE-001-Shi2016-边缘计算愿景.pdf
```

**卡片和 PDF 用同一个编号和短名**，方便对照。

- 三位编号，连续不跳
- 文件名里不能有 `\ / : * ? " < > |`
